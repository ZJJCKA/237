# luci-app-fanctrol

用于当前已实测的 BPI-R3 Mini 固件：`max_state=3`，并且
`cur_state=0 / pwm1=0` 对应实体风扇全速。

> 不要直接用于 `state 0` 表示停转的其他内核或设备树版本。

## 3.2.14

- release 6 修复无线重新配置/重载时一次 `iwpriv` 超时后永久隐藏无线温度的问题：真正不可回收的
  子进程仍会阻止同接口重复启动；该子进程退出后自动解禁，下一次 5 秒采样立即重试。
- release 5 为无线温度命令加入不依赖 `timeout` 的 2 秒内部看门狗；命令超时或异常退出时丢弃输出，
  并追踪仍无法回收的卡死接口，防止后台进程每 5 秒堆积。进程状态无法确认时不会误杀或阻塞等待。
- `CurrentTemperature` 只接受精确字段名，原始整数先限制长度并按十进制规范化，随后严格限制在
  `-40..150` 摄氏度内再换算为毫摄氏度；拒绝伪字段、小数、过长值和越界值。

- 控制开关区域改为左右等分：左侧新增温度来源选择，右侧保留原有开关；
  平板和手机宽度下自动改为上下排列。
- 新增处理器、无线网、5G 模组缓存和固态硬盘四类固定温度来源；
  使用原生单选下拉框，一次只由一个真实可用来源控制风扇。
- 来源选择在鼠标或手指松开时完成 UCI commit，并立即发送 HUP 打断等待，
  不改变原有 1 秒自动温控周期和 1 秒页面状态轮询。
- 无线网使用 5 秒低频运行时缓存，5G 只读取 at-server 提供的
  `/var/run/at-webserver/chiptemp.status`，不会由风扇插件直接争用 AT 串口。
- release 4 删除目标固件不存在的 `stat` 强依赖，改用 BusyBox `find` 精确验证
  缓存目录/文件仍为 `root:root 0700/0600`；`timeout` 不存在时也不会让采集器退出。
- 页面标题、正文、四个温度来源选项、数值和曲线坐标统一使用同一字体家族；
  标题、正文和数值只保留必要的字号与粗细层级，动态数字使用等宽数字特性。
- 新安装默认只选 CPU；升级旧配置时自动补上 CPU 来源并继续保留已有模式、曲线和开关。
- 当前所选来源不可用且控制开启时进入 100% 全速保护；不可用的其他选项不能被新选中。
- 所有未检测到或缓存失效的非当前来源都不会出现在下拉菜单中；恢复检测后会在下一次状态刷新时自动出现。

## 3.2.13

- release 5 将用户主动关闭与故障保护分离：WebUI 关闭后 daemon 继续运行并持续
  输出 0%，下次开机会重新应用已保存的关闭状态；非法开关值、启用状态下温度读取失败、
  daemon 异常退出、普通服务停止和升级停服务仍保持 100% 全速保护。
- 保留 3.2.12 的模式切换和手动滑块平滑显示修复。
- 安装脚本不再重复停止、启动或删除 procd 服务。
- `postinst-pkg` 不再把 ubus 是否在线、服务启动速度或状态文件生成时间作为
  opkg 安装成败条件。
- 服务启停统一交给 OpenWrt 的 `default_postinst` 和 `default_prerm`，避免升级时
  出现重复 `service delete (Not found)`。
- 同时清理 LuCI index、module、template 和 runtime 临时缓存，避免失败安装留下
  混合缓存。
- 编译机源码与辅助构建器均使用标准的 `postinst/postinst-pkg` 和
  `prerm/prerm-pkg` 控制脚本结构。

主要功能：

- 处理器、无线网、5G 模组缓存和固态硬盘四种单选温度来源
- 处理器与固态硬盘读取内核接口；无线网每 5 秒更新运行时缓存；5G 只读 at-webserver 缓存，不占用 AT 串口
- 新安装默认仅选处理器；当前所选温源不可用时全速保护
- 静音、均衡、性能三种模式
- 手动百分比控制和可拖动温度曲线
- 用当前手调曲线覆盖用户选择的预设
- 模式、开关和重置点击后自动保存；滑块与曲线在松手后自动保存
- 普通调节先完成 UCI commit 持久化，再立即 HUP 守护进程生效，不等待固定周期
- 页面刷新后从 UCI 重新读取已保存的三个预设
- 风扇守护进程每 1 秒读取一次 CPU 温度；页面在上一请求结束 1 秒后再刷新，永不叠加请求
- 模式、开关、曲线和滑块松手后的保存成功路径没有额外防抖或 sleep，断电后配置仍保留
- 简体中文翻译直接内置在主包，不需要独立语言包
- 按插件实际可用宽度自动切换桌面三栏、窄屏两栏、平板和手机单栏
- 手机曲线区仅在命中节点时接管拖动，触摸空白处仍可正常上下滚页
- 手机或电脑后打开的风扇页会取得独占控制，旧风扇页停止轮询并退出到状态概览

底层 `/usr/bin/fancontrol` 和 init 脚本继续使用已知可正常工作的 PWM
方向与四档换算。3.2.11 将全新安装的默认均衡曲线调整为
`45°C=40%`、`50°C=59%`、`55°C=79%`、`60°C 及以上=100%`；默认配置的
`mode=1` 为均衡模式。升级安装继续保留已有设备的 UCI 配置，不会擅自覆盖
用户已经保存的曲线。服务停止或卸载时，守护脚本会把该设备安全地留在
`cur_state=0` 对应的物理全速状态。内置翻译使用主包专属的
`fancontrol-bundled.zh-cn.lmo`，避免与旧语言包的文件路径冲突。

3.2.11 对容器宽度做去重后才重排，只有曲线画布尺寸实际变化时才重绘；页面
隐藏、风扇离屏或滚动时会暂停无用动画，手机布局移除了高开销阴影。状态 API
优先读取守护进程生成的紧凑运行时文件，不再为每次页面轮询重复创建 UCI cursor。
跨设备独占只作用于本插件页面，不会强制注销整个 LuCI 会话。

3.2.11 删除独立的“保存并应用”按钮。所有成功的自动保存均执行一次 UCI
commit，因此正常关机或断电后仍会保留；滑块和曲线只在松手时提交，拖动过程
不会逐像素写入闪存。启停开关会同步服务的开机状态，重新启用时仅在服务未运行
的情况下启动，不再无条件重启。

## 生成一体 IPK

```sh
python3 tools/build_ipk.py
```

该辅助脚本会先运行发布契约测试，然后生成一个 `luci-app-fanctrol` IPK 和一个
带完整发布号的编译机源码 ZIP。源码 ZIP 的顶层固定为标准目录
`luci-app-fanctrol/`，可直接解压到 OpenWrt/ImmortalWrt 的 `package/` 下。
主包直接提供中文功能且不依赖、
冲突或替换独立 `luci-i18n-fanctrol-zh-cn`，因此升级失败回滚时不会尝试从
feeds 下载旧语言包；一体包内只包含主包专属的中文 LMO。

3.2.13 保持标准 conffile 所有权。`preinst` 先逐字节备份已有 UCI 文件，再短暂
放入与本版完全一致的维护者默认配置供 opkg 比较，避免手调配置升级时产生
`resolve_conffiles` 提示；uci-defaults 在服务启动前恢复用户配置。整个过程不停止
服务、不访问 ubus，也不直接修改 procd 注册状态；中断保护会在 opkg 未完成时
自动恢复备份。`postinst-pkg` 只清理事务文件、修正权限和清除临时缓存，服务
生命周期始终交给 OpenWrt 标准包装器。辅助构建器生成的直接安装 IPK 使用与
编译机相同的 wrapper 与 `*-pkg` 分层结构。sysupgrade 保留清单同时覆盖活动配置
和升级恢复副本。

如果旧安装意外缺失 `/etc/config/fancontrol`，同一个事务会放入本版维护者配置；
若存在升级恢复副本，解包后的 uci-defaults 会优先恢复原有配置。

本地响应式预览可用 `python3 tools/render_preview.py` 生成，预览目录位于源码
目录的上一级 `_responsive_preview`。
